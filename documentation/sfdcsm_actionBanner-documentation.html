sfdcsm_actionBanner

Lightning Web Component – Technical & Configuration Reference
API version: 62.0 Apex controller: sfdcsm_ActionBannerFlowController Document date: April 2026

1. Overview

sfdcsm_actionBanner is a configurable, full-width banner panel for Salesforce Lightning pages. It displays a coloured bar that can contain an icon, up to two lines of text, and up to two action buttons. Each button can invoke an autolaunched Flow, passing the current record's Id as an input variable.

The component is built with Lightning Design System (SLDS) primitives and automatically adjusts its width to fill the column or region it is placed in.

Visual anatomy

Text Line 1 (bold)

Text Line 2 (regular, smaller)

Button 1 Button 2

All elements visible — icon · two text lines · two buttons

Layout rules: The icon anchors to the left edge; the buttons anchor to the right edge. The text section fills all remaining horizontal space. Elements that are not configured (empty icon name, empty button labels) are completely hidden — the text expands to occupy the freed space automatically.

3. Parameters

3.1 Record Context

ParameterTypeDefaultRequiredDescription
recordId String — Optional The Salesforce Id of the current record. On a Record Page this is populated automatically by the platform and does not need to be set manually. In a Screen Flow it must be assigned from a flow variable (e.g. {!recordId} or a Get Records result). The value is forwarded to any autolaunched flow as input parameter recordId. If left empty, the flow is still invoked but no recordId is passed.

3.2 Appearance

ParameterTypeDefaultRequiredDescription
panelColor String #4CAF50 Optional Background colour of the panel as a CSS hex code. Accepts 3-digit (#0f0) or 6-digit (#00ff00) hex values. Any valid CSS colour string (e.g. rgb(…), named colours) is also accepted. Falls back to #4CAF50 (green) when left empty.
textColor String #ffffff Optional Colour of the text lines as a CSS hex code. Applied to both Text Line 1 and Text Line 2. Falls back to #ffffff (white) when left empty. Choose a colour with sufficient contrast against panelColor for readability.

3.3 Icon

ParameterTypeDefaultRequiredDescription
iconName String — Optional SLDS icon identifier in the format category:name, e.g. standard:email_chatter, utility:info, action:approve.
When left empty the icon area is hidden and the text fills that space.
Full icon catalogue: lightningdesignsystem.com/icons

3.4 Text

ParameterTypeDefaultRequiredDescription
textLine1 String — Optional Primary text line. Rendered in bold at a slightly larger font size. Supports static text and {{FieldApiName}} merge tokens that are resolved against the current record at runtime (record pages only). Example: SLA Breached · {{SLA_Remaining__c}} overdue. Truncates with an ellipsis when the available width is exceeded.
textLine2 String — Optional Secondary text line. Rendered in regular weight at a smaller font size with reduced opacity. Supports the same {{FieldApiName}} merge token syntax as textLine1. Can be left empty independently.
textAlignment String left Optional Horizontal alignment of both text lines within the text area. Accepted values: left · center · right. Any other value is treated as left. In App Builder and Flow Builder a drop-down with all three options is shown.

3.4.1 Merge Field Tokens — Live Record Data

Both textLine1 and textLine2 support inline {{FieldApiName}} tokens. When the component is placed on a Record Page, the platform automatically provides the record's object API name; the component then fetches exactly the fields referenced in the text via Lightning Data Service and substitutes them at render time.

Record pages only. Merge field resolution requires objectApiName, which is injected automatically by the platform only on lightning__RecordPage targets. On App Pages, Home Pages, or Screen Flows, use plain static text or (for flows) flow variable merge syntax from Flow Builder.
What you type in App BuilderWhat renders on a Case record
{{Subject}}Payment gateway timeout on checkout
SLA Breached · {{SLA_Remaining__c}} overdueSLA Breached · 2h 14m overdue
Owner: {{Owner.Name}} · Priority: {{Priority}}Owner: James Cook · Priority: High
{!Account.Name} (on Opportunity page)Acme Corporation

Rules:

  • Use the exact field API name (case-sensitive), including the __c suffix for custom fields.
  • Relationship fields are supported: {{Owner.Name}}, {!Account.BillingCity}.
  • The field must be accessible to the running user; inaccessible fields render as an empty string.
  • Static text and tokens can be freely mixed in the same value.
  • If no tokens are present, the string is rendered as-is with no additional data fetch.

3.5 Buttons

Two independent buttons are available (Button 1 and Button 2). Each button has three parameters: a Label, a Variant, and a Flow. Configuring the same set for Button 2 adds a second button to the right of Button 1. Any button whose label is empty is not rendered.
ParameterTypeDefaultRequiredDescription
button1Label String — Optional Visible label of Button 1. Leave empty to hide the button entirely. Supports Salesforce Custom Label references in App Builder ({!$Label.c.MyLabel}) and flow text resources in Flow Builder.
button1Variant String neutral Optional SLDS visual style of Button 1. See Section 4 for a full description of each variant. Falls back to neutral for unrecognised values.
button1Flow String — Optional API name of an Autolaunched Flow to invoke when Button 1 is clicked (e.g. My_Flow_API_Name). The flow must accept a String input variable named recordId. If left empty the click is a no-op. See Section 5 for flow requirements.
button2Label String — Optional Identical to button1Label for the second button.
button2Variant String neutral Optional Identical to button1Variant for the second button.
button2Flow String — Optional Identical to button1Flow for the second button.

5. Autolaunched Flow Integration

5.1 How it works

When a button is clicked, the component calls the Apex method sfdcsm_ActionBannerFlowController.invokeFlow, passing the flowApiName and the current recordId. Apex instantiates the flow via Flow.Interview.createInterview() and starts it synchronously.

After the flow finishes successfully, getRecordNotifyChange is called (when on a record page) to notify Lightning Data Service that the record may have changed. All LDS-backed components on the page — related lists, field sections, highlights panel, etc. — automatically refresh without a full browser reload.

A loading spinner replaces the buttons while the Apex call is in progress. On completion a toast message confirms success or reports the error.

5.2 Flow requirements

The referenced flow must be of type Autolaunched Flow (No Trigger). Screen flows are not supported because they require UI interaction.

The flow must declare a text input variable with the following properties:

PropertyRequired value
API NamerecordId (case-sensitive)
Data TypeText
Available for input✔ Checked

If the flow does not declare this variable, Salesforce will throw an error when the button is clicked. The variable may be optional inside the flow logic — it only needs to exist as an input variable.

5.3 Record page refresh

Page refresh after a successful flow invocation is automatic on record pages. In screen flows or app/home pages, getRecordNotifyChange is not called (no recordId is available), so no refresh occurs.

6.5 Using a Custom Label as button text

In Lightning App Builder, enter the following in the Button Label field to reference a custom label:

{!$Label.c.My_Custom_Label_Name}

In Flow Builder, create a Text resource of type Global Constant or use the $Label global variable in a formula resource, then bind it to the button1Label input property.

force-app/main/default/
├── lwc/sfdcsm_actionBanner/
│   ├── sfdcsm_actionBanner.html  – Template (layout)
│   ├── sfdcsm_actionBanner.js  – Controller (properties, flow invocation)
│   ├── sfdcsm_actionBanner.css  – SLDS-based styling
│   └── sfdcsm_actionBanner.js-meta.xml  – Metadata (targets, property definitions)
└── classes/
    ├── sfdcsm_ActionBannerFlowController.cls  – Apex (flow invocation)
    └── sfdcsm_ActionBannerFlowController.cls-meta.xml

Deploy all six files together using SFDX:

sf project deploy start --source-dir force-app

Permission: The running user must have access to the Apex class sfdcsm_ActionBannerFlowController via their Profile or a Permission Set, and must have the Run Flows permission to execute the referenced autolaunched flows.
