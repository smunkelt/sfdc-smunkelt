sfdcsm_FilteredPicklist

Lightning Web Component — Technical Reference
API Version 62.0  ·  Author: sfdcsm  ·  Last updated: April 2026

1. Overview

sfdcsm_FilteredPicklist is a reusable Lightning Web Component that renders a picklist field whose available values are automatically filtered to those permitted for a specific Salesforce record type. It is designed for use in Screen Flows and Lightning Record Pages (App Builder).

Unlike placing a standard picklist field directly on a flow screen — which always shows all picklist values — this component respects record-type picklist filters, ensuring users only see the values that are valid for the selected record type.

Key Features

  • Filters picklist values to a specific record type — developer name or record type ID accepted
  • Blank record type → master record type used (shows all values)
  • Flow-ready: output variable, FlowAttributeChangeEvent, and validate() all implemented
  • Required field enforcement blocks flow navigation when no value is selected
  • Optional "--None--" entry at the top of the list
  • Loading spinner and SLDS-styled error handling built in
  • No Apex required for static configuration; Apex used only for developer-name resolution

3. Parameters

3.1 Input Parameters

Parameter Type Required Default Description
objectApiName required String Yes — API name of the Salesforce object whose picklist field you want to display. Examples: Case, WorkOrder, Account.
recordTypeName String No — Identifies the record type to filter picklist values by. Accepts two formats:
  • Developer name — e.g. SDO_Service_Case. Resolved to an ID via Apex SOQL.
  • Salesforce ID — 15 or 18-character record type ID, e.g. 012Wt000000Kb3BIAS. Used directly without an Apex call.
Leave blank to use the master record type, which includes all picklist values.

Tip: In a flow, pass {!$Record.RecordTypeId} to automatically use the record type of the current record.
fieldApiName required String Yes — API name of the picklist field to render. Examples: Status, Priority, SDO_Service_SLA_Type__c.
label String No Select Label displayed above the picklist field.
placeholder String No -- Select -- Placeholder text shown inside the combobox when no value is selected.
includeNone Boolean Boolean No false When true, adds a --None-- entry at the top of the option list, allowing the user to clear the selection.
required Boolean Boolean No false Marks the picklist as required. Displays a red asterisk next to the label. When the user tries to navigate to the next screen without selecting a value, the flow is blocked and an error is displayed (see Section 5).

3.2 Output Parameter (Flow only)

ParameterTypeDescription
value output String The API value of the picklist option selected by the user (e.g. Working, Escalated). Map this to a flow variable in Flow Builder's Outputs tab to use the selected value in subsequent flow elements such as Update Records, Decisions, or Apex Actions.

5. Flow Validation

The component implements the validate() method required by the Flow runtime. When the user clicks Next or Finish on the screen:

  1. The Flow runtime calls validate() on every component on the screen.
  2. If required = true and no value has been selected, validate() returns { isValid: false, errorMessage: 'Please select a value.' }.
  3. The combobox's native SLDS validation UI is triggered (reportValidity()), showing a red border and inline error message directly below the field.
  4. The flow footer displays "Fix errors before continuing" and navigation is blocked.
  5. Once the user selects a value and clicks Next again, validate() returns { isValid: true } and navigation proceeds.
Important: Without the validate() method, the flow treats the component as always valid and allows navigation even when no value has been selected, regardless of the required setting.

6.1 Record type resolution logic

recordTypeName valuePath takenApex fired?
(blank) Master record type ID from Wire 1 (getObjectInfo) No
SDO_Service_Case (developer name) Wire 2 Apex SOQL: WHERE SObjectType='Case' AND DeveloperName='SDO_Service_Case' Yes (cacheable)
012Wt000000Kb3BIAS (ID) Assigned directly in the property setter — no extra wire call No
Caching: The Apex method is annotated @AuraEnabled(cacheable=true). Salesforce caches the result in the Lightning Data Service (LDS) cache. Subsequent renders with the same object + developer name combination do not issue new server calls.

6.2 Why Apex is needed for developer names

The getObjectInfo wire adapter returns a RecordTypeInfo object per record type containing name (the UI label), recordTypeId, and master. The developer name is not reliably present in this response across all org configurations and API versions. Since labels can differ from developer names (e.g. the SDO_Service_Case record type has the label "Case"), matching on the label would silently fail. The Apex SOQL query on the RecordType sObject is the only unambiguous resolution mechanism.
